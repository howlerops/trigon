# Model card — Trigon reference model

This describes the **reference model**, the small trained model committed under
`reports/`. It is a spike whose purpose is that the pipeline closes and the
release gates are exercised by something rather than asserted about something.
It is not a model to deploy, and this card exists partly to say so precisely.

The serving stack, the contract and the eval harness around it are a different
matter and are the actual deliverable; see `README.md`.

## What it is

| | |
| --- | --- |
| Architecture | Prefill-only transformer, no decode loop, no sampler |
| Size | 128-wide, 2 layers, 4 heads — about 5 MB of weights |
| Tokenizer | Byte-level BPE, 5,635 tokens, trained on this repository's own corpus |
| Heads | Categorical only: a slot per option (Choice ≤ 64), one slot dotted with pooled option states (Choice > 64 and Score), one logit (Noul) |
| Training data | Synthetic, outcome-grounded, generated by `trigon.evals.datasets` with 20% label noise |
| Calibration | Temperature fitted on the training split, never on the split the gates read |
| Licence | Apache-2.0, code and weights, no field-of-use restriction |

Every number below comes from a committed report that reproduces from the
command printed at its top.

## What it can do

**Answer typed questions about a state in one pass, with probabilities that
mean something.** It reaches ECE 0.0111 against a 0.05 gate, with the measured
error above its own simulated noise floor — so the calibration is a measurement
rather than sampling luck.

**Answer many questions at once without any of them affecting the others.**
Exactly, to floating-point equality, including at twenty extra questions
(`tests/test_independence.py`). This is a property of the layout, not of
training, so it holds for any model in this architecture.

**Refuse to be confident when it should not be.** Where it is confident it is
right; where it splits evenly between two options it reports confidence near
0.10 and that is the case it gets wrong.

## What it cannot do, and will not learn to

**It has learned one question of three.** Against each question's own marginal
predictor, on held-out data:

| Question | What it needs | Accuracy | Its marginal predictor |
| --- | --- | ---: | ---: |
| `plan` | copy a value out of the state | 0.457 | 0.253 |
| `at_risk` | a conjunction over two fields | 0.650 | 0.667 |
| `size` | a threshold on a number | 0.237 | 0.257 |

`plan` is a copy task and it does it. On the other two it emits an almost
constant answer and lands *below* chance. That is consistent with the project's
documented non-goals — no arithmetic, no counting — and with a two-layer model.

It is also why the per-question release gate is advisory rather than blocking:
this model fails it, and so does every variant tried.

**No arithmetic, no counting, no multi-hop reasoning.** These are explicit
non-goals. The jaggedness suite measures them anyway and publishes the results
with `non_goal = True`, because a benchmark you only run when you expect to win
is not a benchmark.

**It is not a general-purpose model.** It was trained on one synthetic
generator describing SaaS accounts. It has seen nothing else.

## Known limitations of the pieces around it

**The tokenizer is fitted to this repository's corpus.** It is a real
byte-level BPE with an injective vocabulary — a genuine improvement on the
hashing tokenizer it replaces, which collided 24.4% of this corpus — and it
saves 6.8% of prefill on average. But its merges were learned from the eval
corpus and the docs, so it is a good encoding for that text and an ordinary one
for anything else. Phase 1 replaces it with the backbone's own tokenizer.

**There is no KV cache.** The layout makes the schema prefix cacheable and
`tests/test_independence.py` asserts it, but nothing caches it yet.
`usage.cached_schema_tokens` therefore reports 0 on every response, and the
contract says to read that as "not cached", never "not cacheable".

**Training data has no e-commerce domain, and no real resolved outcomes.** The
licence audit (`docs/data.md`) put Amazon ESCI at amber and every
resolved-outcome corpus at red, so outcome grounding rests on verifiable
synthetic data. That is a narrower claim than the build plan assumed.

**The cost argument is unmeasured.** The $0.007/MTok figure the project's
economics rest on is arithmetic over unsourced inputs. It is labelled an
assumption everywhere it appears and needs a burn-in on real hardware.

## How it was evaluated

Four suites, one runner, release gates that exit non-zero:
`trigon eval all -n 200`. The gates are in `src/trigon/limits.py` and the
methodology is in `docs/evals.md`. Two properties of the methodology are worth
repeating here:

**Every published ECE carries a simulated noise floor.** At n=1,000 a perfectly
calibrated model scores a 95th-percentile ECE of about 0.049 — the whole 0.05
gate. A gate that a perfect model fails half the time is not a test, so the run
gates its own measurement before it gates the model.

**Calibration alone certifies nothing.** A model reporting each question's
marginal distribution is calibrated by construction and useless. One committed
run demonstrates this: it scored 0.3887 against a 0.3922 marginal predictor —
worse than ignoring the state — and passed every ECE gate including the
adaptive one. `accuracy_over_baseline` is the term that rejects it.

## Intended use

Exercising the pipeline, reproducing the gates, and as the thing a phase-1
model has to beat. Running the eval harness against your own backend, which is
what the harness is for.

## Uses it is not suitable for

Anything with a consequence. It answers one question of three, it is trained on
synthetic data from one generator, and it is 5 MB. Serving it as though its
probabilities transfer to your domain is exactly the failure the conformal
wrapper in `trigon fit` exists to prevent — fit one on a few hundred of your own
labels, and read the coverage number rather than the ECE.

## Reproducing

```bash
pip install -e ".[dev,server,train]"
# the command at the top of reports/reference-run.md, verbatim
trigon eval all -n 200          # the suites and gates, no weights needed
```

Every committed report prints the command that produced it, is seeded end to
end, and has been re-run from that command to confirm it reproduces every gate
verdict to the digit.
